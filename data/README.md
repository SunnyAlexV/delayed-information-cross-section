# The data, and why it is not here

This folder does not contain the inputs. It contains what is needed to obtain
them and to prove that you obtained the same ones.

Every vendor behind this project's inputs prohibits redistributing their files.
That is not a judgement call about what is polite; it is what the terms say, and
they were read in September 2026 before this folder was emptied:

| source | series | terms, as they read | may we redistribute? |
|---|---|---|---|
| Investing.com | the eight equity indices, VDAX-NEW, the retail VIX export, spot VSTOXX, VSTOXX mini futures | "It is prohibited to use, store, reproduce, display, modify, transmit or distribute the data contained in this website without the explicit prior written permission of Fusion Media and/or the data provider." | no |
| Cboe | `VIX_History.csv`, `VIX9D_History.csv` | permits viewing, printing and downloading **one** copy for personal non-commercial use, and forbids distributing the Materials in whole or in part without prior written consent | no |
| Yahoo Finance | the four `frontier/` series | forbids reproducing, distributing or transmitting any portion of the Services without explicit written permission | no |
| FRED / S&P Cotality | the twenty-metro Case-Shiller panel and the two national Case-Shiller series | FRED labels these **"Copyrighted: Pre-approval Required"**: without the copyright holder's written permission the data "may only be used for non-commercial educational or personal use" | no |
| FRED / FHFA | `illiquid/USSTHPI_fred.csv` | FRED labels this **"Public Domain: Citation Requested"** | **yes**, and it is here |

One file of thirty-five is redistributable and it is the one still in this
folder. Using the rest to do research and publishing the results is a different
act from republishing the files, and only the second is what these terms forbid.

## What ships instead

`MANIFEST.tsv`, one row per input file:

| column | what it is for |
|---|---|
| `source`, `redistributable` | which vendor, and whether the file could have been included |
| `bytes`, `rows` | catches a truncated or half-written download, which a digest reports only as "different" |
| `first`, `last` | the date span, so a fresher export can be recognised as a fresher export |
| `sha256` | the exact bytes the paper's numbers were computed from |
| `series_sha256` | the digest of the **derived** series: date and every numeric column, rounded to four decimals, in a fixed text form. This is what makes a fresh export checkable — a reader whose export agrees with ours on every date inside our span matches here even though the files differ |
| `year_sha256` | the same digest taken one calendar year at a time, eight hex characters each. It publishes no value and no date, and it turns "your file disagrees somewhere" into "your file disagrees in 2008" |

The last two columns are the point. A digest over a vendor's CSV is a statement
about that vendor's formatting. A digest over the closing prices actually fed to
the estimator is a statement about the input to the experiment, and it survives
the vendor adding a month of rows.

`CONVENTIONS.tsv`, alongside it, records how those bytes are interpreted rather
than what they are: each series' close time in UTC, whether it contributes
today's session or yesterday's to a New York target, and why. A digest proves a
replication is reading the same numbers; this proves it is reading them the same
way. Both notes at the top of that file matter — daylight saving is ignored
because it moves a close by an hour and never reorders the blocks, and a day on
which any series is missing is dropped from that model's rows rather than
imputed. It is generated by `build_manifest.py` from `lab05_robustness`, so it
cannot drift from the code that applies the rules.

## How to obtain each file

**The eight equity indices, VDAX-NEW and the VSTOXX series** — Investing.com's
historical-data page for each instrument, "Download Data", daily frequency. The
provider caps a single export at 5,000 rows, which is why each series arrives as
two files with a deliberate overlap; `MANIFEST.tsv` gives the span of each half,
and `lab47_target_seam.py` audits all nine joins. Columns are
`Date, Price, Open, High, Low, Vol., Change %`, where `Price` is the close. The
spot VSTOXX is filed under "STOXX 50 Volatility VSTOXX EUR", symbol **V2TX**; a
search for "VSTOXX" returns the futures contracts instead, which is a different
series and must not be concatenated with it.

**VIX and VIX9D** — Cboe's own published histories, `VIX_History.csv` and
`VIX9D_History.csv`, columns `DATE, OPEN, HIGH, LOW, CLOSE`. These are the
series the paper uses; the Investing.com VIX export is read by
`lab43_official_vix.py` alone, which audits one against the other.

**The four frontier indices** — Yahoo Finance daily history for `^KSE`, `^JKSE`,
`^CSE` and `^KLSE`, saved one file each. Two of the four stop in September 2021,
where that vendor's history for them ends.

**The housing panel** — FRED. The twenty metro series are the `XRNSA` family
(`BOXRNSA`, `CHXRNSA`, and so on; `lab55_illiquid_measured.py` lists all twenty
with their cities), downloaded as one table on a monthly frequency with
`observation_date` as the first column. `illiquid/PROVENANCE.md` records the
digest of every series computed at the source before transfer, and the single
transformation applied afterwards: a rounding to four decimals whose largest
relative error anywhere is 1.0e-6.

**`single_market/XYZ.csv`** — a shorter S&P 500 export read only by `lab02`. It
is kept in its own folder because the file discovery in the later labs globs
`data/*.csv` and would otherwise treat it as a third S&P chunk. The same reason
puts `frontier/` and `illiquid/` in folders of their own.

## Then

```
python make_all.py --data <folder>              # all of the below, in the right order
```

or, separately:

```
python verify_data.py  <folder>                 # per file: IDENTICAL, SAME DATA or DIFFERENT
python run_all.py --check --data <folder>       # all 58 scripts against the stored output
python build_pdf.py                             # render the three documents
python verify_paper.py                          # every figure in them against that output
```

`verify_data.py` reports one of four states per file. `IDENTICAL` means your
bytes are ours. `SAME DATA` means the files differ but every row inside our date
span agrees, which is what a later export looks like. `DIFFERENT` means you and
we disagree on a date we both hold, and names the calendar years — that is not a
stale export but a different series, and it explains any mismatch in the results
without anyone having to read the code. `MISSING` is self-explanatory.
